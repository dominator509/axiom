# L2.5 — LLM Gateway, TOKENKILLER & Generation

## Unified LLM harness (F-33, F-35)

A LiteLLM-style router in the Orchestration plane exposes one internal API and routes to OpenAI, Grok, Anthropic, DeepSeek, Venice, and local vLLM/Ollama. Per-provider cache toggles (DeepSeek prefix caching, Anthropic prompt caching, OpenAI automatic caching) are honored by structuring payloads to each provider's caching contract. Per-org budget caps + alerts guard against cost blowout (R-06); local vLLM is the zero-marginal-cost fallback (F-40).

## TOKENKILLER prompt assembly (F-34, LBI-09)

Every call assembles ordered, block-aligned segments. Static segments are byte-stable so provider prefix caches hit; only `S3` varies per call. Target ≥97% cache-hit (NFR-03).

```
S0  ── Persona / system (per model, static)           ┐
S1  ── Playbook + ToS rules (static)                  │  cached prefix (byte-stable,
S2  ── Retrieved viral exemplars (semi-static, top-K) │  64-token block aligned)
S3  ── Task variables / analytics / user input (dynamic) ┘  uncached suffix
```

- **S0 persona** is stored once per model and reused verbatim → character consistency (F-41).
- **S1 playbook + ToS** is the Fanvue Creator Course guideline set + platform ToS rules injected as static text (F-56).
- **S2 exemplars** are the top-K high-performing recipes retrieved from the viral store (`L2.8`). Placing them in S2 (not S3) keeps them cache-friendly across a generation batch for the same model/platform while still being fresher than S0/S1. Exemplar set changes only when new high-performers are labeled.
- **S3** carries the actual task JSON (shoot config, analytics, revise instructions).

Segment boundaries are padded to 64-token blocks; transcripts are append-only; a cache-hit-rate metric is emitted per call to Observability and regressions alarm.

## Photoshoot Auto-Generator & Master Prompt Engine (F-36)

Cron- or operator-triggered. UI dropdowns (Attire, Environment, Props, Colors, Time of Day, Lighting, Ambience) compile to a JSON block injected into the Master Prompt (as S3). The engine:
1. Retrieves the model's top-K viral exemplars for the target platform(s) → S2.
2. Generates 5 distinct image prompts + caption variants + per-platform hashtag sets.
3. Sends each image prompt to the image backend; produces variants (`asset_variants`, crop tracking F-13).
4. Routes every variant through the **local ToS vision model** (per platform, `L2.10`).
5. Hands the bundle to the **Relay** (`L2.7`) for on-the-go approval.

## Caption & adaptation generation (F-29, F-30)

- **Long→short clipping** briefs and captions are generated here; the actual clipping runs on the Rust media plane.
- **Cross-platform adaptation** reformats a source post into each platform's native form with tone/hashtags tuned to platform culture and ToS. Each output is a distinct `post_target` and is independently ToS-gated.

## Community persona agents (F-38–F-42)

- **Private hub agents** (Telegram/Discord via OpenClaw) route to Venice (`venice-uncensored-role-play`) or local vLLM (abliterated) for immersive, private persona modeling. Persona lives in S0.
- **Public SFW funnel agent** (X/IG/Reddit) runs under a forced SFW system prompt, human-like jitter (2–8 min via the queue), strict ToS compliance, and a conversion objective: build rapport, then route to the model's private channel by injecting the invite link (F-42).

## Fanvue Creator Course Playbook Engine (F-54–F-57)

- **Guideline DB** (structured JSON) of optimal times, cadence, upsell strategy.
- **Scheduler validation:** the calendar cross-references scheduled posts against the playbook and flags under-cadence models (F-55).
- **Prompt enrichment:** relevant guidelines are injected into S1 so all AI output natively follows the course methodology (F-56).
- **Adherence scoring:** MCP-pulled analytics are graded against course KPIs → a Course Adherence Score per model, surfaced on the dashboard and tracked over time (F-57).

## Gateway safety & routing rules

- All generation output flows to the ToS gate before it can be scheduled (LBI-07).
- Provider selection considers cost, capability (vision vs text), privacy (private-hub traffic prefers Venice/local), and budget caps.
- Every call is traced (correlation ID) and its cache-hit-rate + token counts recorded for the cost model (`appendices/A1`).
