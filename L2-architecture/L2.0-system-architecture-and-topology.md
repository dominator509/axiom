# L2.0 — System Architecture & Deployment Topology

## Plane model

AXIOM is organized into planes, each independently deployable and scalable. This is the AETHER-style separation applied here: a thin client, a TypeScript orchestration brain, and a Rust hot-path plane, plus stateful backing services.

```
┌──────────────────────────────────────────────────────────────────────┐
│  CLIENT PLANE                                                          │

└───────────────┬───────────────────────────────────┬──────────────────┘
                │ REST/tRPC                          │ (mobile shares API)
                ▼                                     ▼
┌──────────────────────────────────────────────────────────────────────┐
│  ORCHESTRATION PLANE  (TypeScript · Hono BFF + Next Route Handlers)   │
```

### Why this split
- **Client** stays dumb and fast (RSC for data-heavy dashboards, mobile shares the same API surface — F-88).
- **Orchestration** in TypeScript because the LLM SDKs, MCP SDK, auth, and web framework ecosystems are strongest there. Uses **Hono** (not NestJS) for the worker/API surface: far lighter, faster cold start, lower memory — a cost + speed win over v1's NestJS.
- **Hot-path in Rust** because media processing, egress binding, scraping, and local vision are CPU/RAM-bound; Rust cuts instance size and latency (cost + speed). This is where the fail-closed egress guard lives (LBI-02).
- **State plane** consolidates queue + vectors + time-series into Postgres, removing Redis as a hard dependency (cost + fewer attack surfaces). Redis remains optional for high-throughput caching/rate tokens.
- **Relay** and **Observability** are cross-cutting and wire into the operator's phone.

## Deployment topology (cost-optimized default)

**Single-box default** (NFR-01): one Hetzner dedicated or cloud box (e.g., AX/CPX line) running everything under **Coolify** (self-hosted PaaS) as containers, with **Cloudflare** in front (CDN, WAF, DNS, cache) and **Cloudflare R2** for media (zero egress). This replaces v1's Vercel + Fly.io + Neon triad and its metered billing.

```
Cloudflare (DNS · CDN · WAF · cache · Access)
        │
        ▼
  Hetzner box (Coolify)
   ├ next-dashboard (container)
   ├ hono-bff (container)            ── Postgres (RLS+Timescale+pgvector+pgmq)
   ├ rust-hotpath (container, NET_ADMIN for netns/WG)
   ├ relay-router (container)
   ├ glitchtip + prometheus + grafana (containers)
   └ vllm (optional, GPU box or spillover to Venice/API)
        │
        ▼
   Cloudflare R2 (media, SSE)
```

**Managed swap-ins (optional, documented in L2.1):** Vercel for the dashboard, Neon/Supabase for Postgres, Fly.io for the Rust plane, Upstash for Redis, Sentry for crash tracking. None are required; all are drop-in because the code targets standard interfaces (Postgres wire, S3 API, OTel, Sentry protocol).

**Scale-out path:** when one box is not enough, peel planes onto their own boxes in this order: (1) Rust hot-path (most CPU), (2) Postgres (managed or replicated), (3) dashboard/BFF behind a load balancer. No schema or code change required (NFR-09).

## Global kill switch (F-12, LBI-11)

A single control flips an org-level `publishing_enabled=false` flag and broadcasts a drain signal. The scheduler stops dequeuing publish/DM jobs, in-flight jobs finish or checkpoint, and all Relay/DM agents suspend — within 5 seconds. The flag and broadcast are audited. Implementation detail in `L3.4`.

## Data flow: generate → publish (canonical)

```
Generator ─► ToS local vision (per platform) ─► Relay card ─► operator decision
   ─► state:Scheduled (audited) ─► scheduler dequeues at slot
   ─► Rust worker: fetch egress cfg ─► bind netns/WG (health-gated, fail-closed)
   ─► Pre-Post Script ─► connector.publish(idempotency_key) / Fanvue MCP
   ─► attribution UTMs ─► performance ingestion ─► viral labeling/embedding
```
