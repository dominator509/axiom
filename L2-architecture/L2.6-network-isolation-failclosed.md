# L2.6 — Network Isolation & Fail-Closed Egress

## Purpose

Prevent cross-account association by routing each model's outbound traffic through its own dedicated egress, and — critically — **fail closed** so a tunnel failure never leaks the host IP (LBI-02, NFR-06). This is standard multi-account agency hygiene framed around account integrity, privacy, and security.

## Per-model egress config (F-02, F-43)

`model_network_configs` stores the egress mode and (encrypted) credentials:
- `direct` (no isolation — explicit opt-in only)
- `socks5` / `http` / `https` proxy
- `wireguard` (interface + keys)
- `vpn`

The Network & Security tab shows real-time health for each (last check, latency, current egress IP as seen by an echo endpoint, pass/fail).

## Where binding happens (Δ vs v1)

v1 bound proxies in the Node worker via `socks-proxy-agent` / `https-proxy-agent` / WireGuard interface binding. v2 moves egress binding into the **Rust hot-path plane** and wraps each model's outbound work in a **Linux network namespace (netns)**:

```
Rust worker picks up job(model_id)
  ├─ load model_network_configs (decrypt in-memory)
  ├─ ensure per-model netns exists; attach WG/SOCKS route inside it
  ├─ HEALTH CHECK inside the netns (echo IP endpoint):
  │     pass → proceed
  │     fail → ABORT, requeue, emit Sev-1 candidate; NO host-route fallback
  ├─ run all connector/MCP/scrape calls INSIDE the netns
  └─ on completion, zeroize creds, detach
```

The netns is the enforcement boundary: code running for Model A physically cannot reach the network except through Model A's egress, because the namespace has no default route to the host's interface. This makes LBI-02 a property of the OS, not just of application discipline.

## Fail-closed guarantee

- If the tunnel is down or the health check fails, the job **aborts and requeues** with backoff; it is never executed over the host route.
- Repeated failures cross a threshold → Sev-1 incident → auto-page via Relay (`L2.9`, `L2.7`) with a one-tap "pause this model's publishing" action.
- Optional health-gated **failover to an alternate approved egress** for the same model (if configured) — never to `direct` unless `direct` is the explicitly chosen mode.

## Health monitoring

- Continuous per-tunnel health checks (interval configurable) feed the Network & Security tab and Prometheus.
- An egress IP that changes unexpectedly (proxy rotation) is recorded; if a model's expected-IP policy is set, drift triggers a warning.

## Interaction with connectors & MCP

Every `SocialConnector` call, every Fanvue MCP call, and every scraper task for a given model executes inside that model's netns. The connectors receive an HTTP client already bound to the namespace; they cannot construct an unbound client (the client factory is namespace-scoped). This closes the "forgot to pass the agent" class of leaks that plagues per-request proxy wiring.

## Threats addressed

- **Cross-account association (R-04, LBI-02):** OS-enforced isolation + fail-closed.
- **Silent host-IP leak on tunnel failure:** impossible by construction (no default route in netns).
- **Credential exposure:** proxy/WG creds are envelope-encrypted, decrypted only in the Rust worker's scoped buffer, zeroized after (LBI-05).
