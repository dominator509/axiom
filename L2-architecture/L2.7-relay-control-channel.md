# L2.7 — Relay Control Channel (On-the-Go Generation Control)

## Requirement satisfied

When a photo/video is generated, a message is pushed to a channel of your choice (Telegram, iMessage, Signal, or Discord) containing the preview, mock captions, and per-platform hashtags/ToS info, and you control **what happens next right from that channel** while on the go. This is the promoted, first-class successor to v1's "Omnichannel Approval Router."

## Channels (F-71)

| Channel | Transport | UI |
|---|---|---|
| Telegram | Bot API (grammY) | inline buttons + reply |
| Discord | bot + interactions (discord.js) | buttons/select menus + reply |
| iMessage | BlueBubbles | text protocol (numbered/keyword replies) |
| Signal | signal-cli | text protocol (numbered/keyword replies) |

A model's `relay_bindings` decide which channel(s) receive its cards; multiple bindings are allowed (e.g., Telegram for approvals + Discord for incident pages).

## The generation card (F-68)

On every generated asset bundle, the Relay Router composes a card:

```
[preview image / video thumbnail]
Model: Aria   ·   Bundle #4821   ·   3 variants
Caption A: "…"   Caption B: "…"   Caption C: "…"
Hashtags:  IG:#… #…   X:#… #…   TikTok:#… #…   Reddit:(subs)…
ToS:  IG 78 / thr 20  ⚠   ·   X 78 / thr 85 ✓   ·   TikTok 78 / thr 40 ⚠
Targets (proposed): IG, X, TikTok, Reddit, Threads
Price (Fanvue PPV): $9.00
[Approve all] [Approve platforms…] [Edit caption] [Change price]
[Reschedule] [Regenerate] [Revise…] [Hold] [Reject]
```

- Preview media is delivered as an attachment (Telegram/Discord/iMessage/Signal all support media), never a secret-bearing link.
- ToS scores per platform come from the local vision model (`L2.10`); over-threshold platforms are flagged and excluded from "Approve all" unless explicitly overridden (LBI-07).

## Control actions (F-69)

| Action | Effect |
|---|---|
| Approve all | schedule all under-threshold targets at proposed slots |
| Approve platforms… | pick a subset (e.g., X + Reddit only) → schedule just those `post_targets` |
| Edit caption | reply with new text (per-platform or global) |
| Change price | set Fanvue PPV price |
| Reschedule | set a new slot (natural language parsed: "8pm", "tomorrow 9am") |
| Regenerate | re-run the generator (new variants) |
| Revise… | reply with instructions → LLM revises captions/prompt, new card |
| Hold | park in `AwaitingApproval`; no expiry until acted on |
| Reject | discard bundle (audited) |
| Open editor | deep-link to the full dashboard editor for heavy edits (F-72) |

Button channels (TG/Discord) use interactive components; text channels (iMessage/Signal) map the same actions to keywords/numbers (e.g., reply `2 X,Reddit` to approve platforms X and Reddit; `cap A: new text`).

## Command security (F-70, LBI-04)

Every actionable control carries a **signed, single-use, short-TTL command token**: `HMAC-SHA-256(channel_key, {bundle_id, action, nonce, exp})`. On callback the Router verifies signature, checks the nonce is unused (replay protection), checks `exp`, binds to the channel identity, and records signer + token id in the hash-chained audit (LBI-06). A forged or replayed command is rejected and logged (R-07). **Sensitive actions** (network-config changes, granting an agent Autonomous tier) are **not available via Relay** — dashboard only.

## Lifecycle integration

```
Generator ─► ToS scores ─► Relay card ─► operator action (signed)
   ─► state transition (Draft→Scheduled / Held / Rejected, audited)
   ─► scheduler fires at slot ─► egress-bound publish (idempotent)
```

The Relay also carries: incident auto-pages (`L2.9`, F-78), weekly digests (F-28), and viral-loop insights (F-85) — all as cards, so the phone is the single pane of glass for operations on the go.

## Reliability

- Card dispatch is a queued `relay_dispatch` job (durable; retried).
- If a channel is down, cards queue and the operator can act via the dashboard; no bundle is lost.
- Every inbound command is idempotent (single-use token), so a duplicate tap is a no-op.
