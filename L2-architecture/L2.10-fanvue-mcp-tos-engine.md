# L2.10 — Fanvue MCP Integration & ToS Risk Engine

## Fanvue MCP client (F-03, F-31)

The Orchestration plane acts as an MCP client to `https://mcp.fanvue.com/mcp` over OAuth 2.0, all traffic bound to the model's egress (LBI-02).

- **Publishing:** `custom__start-image-upload` → `custom__create-image-post` handle media upload, caption, pricing, scheduling natively. Every publish carries an idempotency key (LBI-03) so retries can't double-post.
- **Agentic inbox:** MCP tools read unread chats and draft replies; the public/private persona agents (`L2.5`) operate here under permission tiers.
- **Analytics sync:** a cron `ingest_metrics` job pulls subs/earnings/messages/tips into `fanvue_metrics` and the Timescale hypertables, feeding the fan CRM, viral loop, and Course Adherence Score.
- **Top-spender tracking (F-06):** pulls top tippers/subscribers, applies tags (Whale/Loyal/Expired), and updates `fan_crm_contacts`.
- **Churn rescue (F-20):** sub-expiry events trigger a targeted MCP DM with a discount (a trigger rule, `L2.2`).

Adapter isolation + contract tests protect against Fanvue MCP surface changes (R-03).

## Pre-Post Script hook (F-09)

A mandatory, abstracted execution space in the queue lifecycle. Both photos and videos are routed through this isolated block **before** being handed to the Fanvue MCP (or any connector). The architecture makes no assumptions about the script's logic — it processes the binary stream and moves the result to a staging area. In v2 this runs on the Rust media plane (faster, isolated) and its execution is recorded in `pre_post_runs` for auditability.

```
[Scheduled trigger] ─► [Fetch raw asset from R2]
   ─► [Pre-Post Script (abstracted, Rust-isolated)]
   ─► [staging] ─► [Fanvue MCP: start-image-upload → create-image-post]
                    / or [SocialConnector.publish(idempotency_key)]
```

## ToS Risk Engine (F-32, LBI-07)

Routes all planned content through classification **before scheduling**:

1. **Content classification (local).** A self-hosted vision model scans each photo/video variant and assigns a **Risk Score 0–100** based on exposure/provocative posing. Running locally on the Rust plane keeps sensitive media in-house and avoids per-image API fees (cost + privacy, Δ vs v1).
2. **Platform ruleset mapping.** A DB of per-platform ToS thresholds (e.g., IG 20, X 85, TikTok 40, YouTube 30 …), tunable per org and per model.
3. **Interception & override UI.** If a variant's score exceeds a target platform's threshold, the UI (and the Relay card, `L2.7`) flags it: *"Variant scores 78/100; Instagram threshold is 20. Proceed anyway?"* Overrides are **per-post, per-platform**, never blanket, and are written to the hash-chained audit (LBI-06, LBI-07).

The ToS gate sits between generation and scheduling for **every** connector and Fanvue, and its scores populate the per-platform figures shown on the Relay card.

## Compliance interlock (LBI-12)

A model with missing/expired Consent & Records (`L0.1`, F-87) is blocked from publishing regardless of ToS scores, and the operator is paged. This precondition is checked at schedule time and again at publish time.
