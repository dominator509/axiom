# L2.4 — Link-in-Bio Providers (Pluggable, All Optional)

## Requirement satisfied

The system must **not require** Fanlynks or Linktree (or both). Providers are optional and composable: a model may run **zero, one, or several simultaneously**. The default requires nothing external.

## Current implementation boundary

Only the Native provider is currently production-enabled. Fanlynks, Linktree, and Beacons remain planned adapters and are deliberately rejected by the API and hidden from the dashboard until their provisioning/OAuth, revocation, link synchronization, and analytics ingestion paths are implemented. A `linkbio_provider` database row alone is not evidence that an external provider is connected.

## Provider abstraction

A planned `LinkInBioProvider` interface has four provider slots, selected per model via `linkbio_providers` rows (0..n active). Only the Native implementation is shipped in this release; the external rows below describe future adapter contracts, not active integrations:

| Provider | Requires | Deploy | Analytics source |
|---|---|---|---|
| **Native** (default) | nothing external | rendered by the CRM at the edge (Cloudflare-cached route `m.<domain>/<slug>`) | first-party (our own click events → `linkbio_analytics`) |
| **Fanlynks** (optional) | the user's Fanlynks repo | provisioned Docker container / Vercel subdomain **only if enabled** | GA4/GTM/Meta Pixel ingest |
| **Linktree** (optional) | Linktree account | none (their hosting) | Linktree API |
| **Beacons** (optional) | Beacons account | none | Beacons API |

### Native provider (new, F-52)
A CRM-hosted link page: server-rendered, Cloudflare-cached, themeable per model (links, colors, branding, avatar), backed by the built-in shortener (F-22) so every outbound link is a tracked `short_link` with per-post UTMs (F-23). Because it is part of the app, it is the **cheapest, fastest, and zero-dependency** default — a new model is instantly live with a link page and full first-party analytics, no external service touched.

### Fanlynks provider (F-49, future adapter)
When implemented and explicitly enabled, the Deployment Engine will provision a Fanlynks instance (Docker/Vercel subdomain), inject the model's links/colors/branding via env/config API, and ingest GA4/GTM/Meta Pixel data via the Google Analytics Data API and Meta Graph API into TimescaleDB. It is not currently exposed or provisioned.

### Linktree / Beacons providers (F-50, F-51, future adapters)
These are planned OAuth/API integrations that will push the model's link set and pull click analytics. They are not currently exposed or enabled.

## Composition & normalization

- In this release a model's production `linkbio_providers` set is `{}` or `{native}`. Future adapter work may expand this set after its external contract and lifecycle are verified.
- **Which link do we hand out?** A per-model **primary provider** setting decides the canonical URL injected into social bios, funnel DMs, and content-link shares. Non-primary providers still collect analytics (useful for A/B'ing link pages).
- **Normalized analytics (F-53):** the Native provider feeds first-party click analytics today. Future adapters must feed the common `linkbio_analytics` shape `(provider, ts, visits, unique, source, clicks, ctr, conversions)` before cross-provider reporting is enabled.
- **Attribution tie (F-23):** clicks from any provider that pass through the built-in shortener carry UTMs; the Attribution Engine joins click events to Fanvue subscription/PPV events (via MCP) to prove per-post ROI.

## Deployment engine changes vs v1

- v1 auto-deployed Fanlynks per model. **This release deploys nothing by default** — the Native provider needs no deploy. External provisioning is deferred until the adapter lifecycle is implemented and tested.
- Teardown remains a required future contract: disabling an external provider must deprovision its instance (Fanlynks) or revoke its tokens (Linktree/Beacons) and stop ingesting, while retaining historical analytics.

## Data model touchpoints

`linkbio_providers(model_id, kind, is_primary, config_encrypted, status, provisioned_at)` and `linkbio_analytics(model_id, provider, ts, …)` (see `L2.2`, DDL in `L3.1`). Provider configs (API tokens) are envelope-encrypted like any other secret (LBI-05).
