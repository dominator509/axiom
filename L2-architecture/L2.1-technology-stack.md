## Notable stack decisions

- **Why keep TypeScript for orchestration but add Rust?** The value-dense, ecosystem-heavy work (LLM routing, MCP, auth, web) is fastest to build and maintain in TS. The value is in *where* Rust is applied: the narrow, hot, security-critical paths (media, egress, vision) where Rust's performance and memory safety pay off directly in instance cost and in fail-closed guarantees. This mirrors the AETHER three-plane split and UltraCortex's Rust substrate.
- **Why Postgres for the queue?** Removing Redis eliminates a whole stateful service to secure, back up, and pay for. `river` (Rust) and `graphile-worker` (TS) both give durable, transactional jobs co-located with domain data, so a publish and its idempotency ledger commit atomically (LBI-03). Redis returns only if a workload genuinely needs sub-ms token buckets at very high QPS.
- **Why Better Auth over Clerk/Auth0?** Per-MAU pricing is a poor fit for a B2B-orgs product that may hold many low-activity model logins. Better Auth self-hosts, supports organizations/RBAC/magic links, and keeps identity data on your own box. Keycloak/Authentik remain the enterprise-SSO swap-in.
- **Why local vision for ToS?** The workload is NSFW-adjacent and high-volume; sending every variant to a third-party vision API is both a recurring cost and a privacy exposure. A self-hosted classifier on the Rust plane is cheaper and keeps sensitive media in-house.
