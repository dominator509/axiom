# L2.9 — Observability & Incident Plane (Auto Bug/Crash Reporting)

## Implementation status

The API and queue worker now include an optional server-side Sentry-compatible
SDK. A configured `SENTRY_DSN` enables correlation-tagged API/job exceptions
and sampled traces; request bodies, cookies, query data, user identity, and
unapproved headers are removed before events leave the process. With no DSN,
the SDK remains disabled. This source wiring does not prove a live GlitchTip
receipt.

The dashboard/mobile surfaces still use the durable RLS-scoped `crash_report`
sink. Next.js, Rust, Relay, log shipping, alert delivery, source-map upload, and
external GlitchTip/Loki/Grafana/OTel deployment remain separate release work.
The L5 verification checklists remain authoritative for those gates.

## Components

| Concern | Default (self-host) | Swap-in |
|---|---|---|
| Crash/error tracking | **GlitchTip** (Sentry-compatible) | Sentry |
| Structured logs | JSON logs → Loki (or file+ship) | Datadog/Grafana Cloud |
| Metrics | **Prometheus** | Grafana Cloud |
| Dashboards/alerts | **Grafana** | — |
| Traces | **OpenTelemetry** collector | vendor OTel |

All planes (Next dashboard, Hono BFF, Rust hot-path, Relay) emit to this plane.

## Automatic crash/bug reporting target (F-73)

- Target: every service initializes the Sentry-compatible SDK (GlitchTip DSN). The API and worker source now initialize it early, capture handled request/job failures with correlation IDs, and set release/environment tags; the Node SDK also installs process-level error handlers. Rust panic capture and dashboard/Relay instrumentation remain unimplemented. A real GlitchTip delivery/readback is still an external acceptance gate.
- Errors are **grouped/deduped** by fingerprint so a recurring bug is one issue with a count, not noise.
- Source maps (frontend) and debug symbols (Rust) are uploaded per release so traces are readable.
- Release tracking ties regressions to a deploy (marker-gated deploys emit a release marker, LBI-10).

## Structured logging & correlation (F-74)

- One JSON log schema across services: `{ts, level, service, correlation_id, org_id?, model_id?, job_id?, event, …}`.
- A correlation ID is minted at the edge (request) or at job enqueue and threaded through every hop (BFF → queue → Rust worker → connector call), so a single publish can be traced end to end.
- Secrets are never logged (LBI-05); a log scrubber strips known-sensitive fields defensively.

## Metrics & traces (F-75)

- Golden signals per service (latency, traffic, errors, saturation) + domain metrics: publish success rate, ToS-block rate, cache-hit rate (TOKENKILLER), egress-health, queue depth, dead-letter count, per-connector error rate, Course Adherence Score, viral-label rate.
- OTel spans wrap generation, ToS scoring, egress bind, publish, and MCP calls.

## Health checks (F-76)

- Liveness/readiness per service.
- **Per-egress tunnel health** (from `L2.6`) is a first-class metric; a failing tunnel shows on the Network & Security tab and in Grafana.

## Dead-letter & replay (F-77)

- Every job type has a dead-letter path. Failures land in `dead_letter` with full context and the original payload.
- Replay is **idempotent by construction** (publish carries idempotency keys, LBI-03), so replaying a partially-succeeded publish cannot double-post.
- The dashboard has a DLQ view: inspect, replay, or discard, per job.

## Severity classification & auto-paging (F-78)

A classifier assigns severity on capture:
- **Sev-1** — cross-account egress risk (LBI-02 breach candidate), audit-chain break (LBI-06), publishing-wide failure, secret-handling error. → **auto-page the Relay immediately** with a one-tap mitigation (e.g., "pause this model," "global kill switch").
- **Sev-2** — single connector down, elevated error rate, DLQ growth. → Relay card (batched) + Grafana alert.
- **Sev-3** — transient/retriable. → logged/counted; alert only if it crosses a rate threshold (crash-loop detection).

**Crash-loop detection:** if the same fingerprint recurs > N times in a window, escalate one level and pause the offending job class rather than thrash.

## Reporting (F-27, F-57)

White-label monthly PDFs (Rust `typst` or headless-Chromium templating) and the Course Adherence Score dashboards are generated from the same metrics/analytics store, so operator-facing reports and internal observability share one source of truth.

## How this ties to the operator

The Relay is the delivery mechanism for anything the operator must know now (Sev-1/2), and Grafana is the deep-dive surface. The operator never has to be watching a screen to learn something broke — it comes to their phone (NFR-08, NFR-11).
