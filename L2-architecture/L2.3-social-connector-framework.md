# L2.3 — Social Connector Framework (10 Networks)

## Design

One uniform interface, per-platform adapters, and an explicit **capability matrix** so the system is honest about what each platform's official API allows (LBI-08). No adapter pretends to do something the API forbids; unsupported actions degrade to `link-share` (post a link with media handled elsewhere) or `manual-assist` (queue a Relay task for a human) rather than failing silently.

### The `SocialConnector` capability set

Each adapter implements the subset it truly supports and declares the rest:

| Capability | Meaning |
|---|---|
| `auth` | OAuth/token connect + refresh |
| `publish.image` / `publish.video` / `publish.carousel` / `publish.story` / `publish.short` | native media publish |
| `publish.text` | text/thread post |
| `schedule.native` | platform-side scheduling (vs. our queue firing at slot) |
| `link_share` | post a URL/card (used where native media publish is unavailable) |
| `read.insights` | fetch analytics |
| `read.comments` / `moderate` | read + hide/delete/block |
| `dm.read` / `dm.send` | direct messages |
| `listen` | keyword/trend monitoring |

Every adapter runs under the model's egress (LBI-02), the ToS gate (LBI-07), idempotency (LBI-03), and per-platform rate limiters. Publishing is fired by our scheduler at the chosen slot unless `schedule.native` is used.

## Per-platform adapter notes

**Instagram (F-58).** Instagram Graph API Content Publishing: create media container → publish. Supports feed image, carousel, Reels, and Stories for Business/Creator accounts linked to a Facebook Page. Insights via the Graph insights edges. Comment read + hide/delete + keyword moderation (F-21). DMs are limited to messaging-API-eligible conversations; otherwise `manual-assist`.

**TikTok (F-59).** Content Posting API for direct-post and upload flows (requires approved scopes and app review). Display API for post/profile analytics. No general DM API → `dm` unsupported. Listening via trend/keyword scraping on the Rust plane (F-17).

**X (F-60).** API v2 for tweets, threads (reply chains), media upload, and DMs. **Access tier drives cost and limits** — the adapter reads the org's tier and disables capabilities the tier lacks rather than erroring. Hide-reply + block for moderation.

**YouTube incl. Shorts (F-61).** Data API v3 `videos.insert` uploads; a video qualifies as a **Short** when vertical, ≤3 min, and tagged `#Shorts`. Playlists, thumbnails, captions. YouTube Analytics API for insights; comment threads for moderation. Quota-aware rate limiting (uploads are expensive in quota units).

**Reddit (F-62).** Submit text/link/image posts and comments; honor each subreddit's posting rules and rate limits; mod actions where the account has permissions; subreddit monitoring feeds the Trend Radar (F-17). Reddit is DM-capable.

**Threads (F-63).** Threads API: publish text/image/video and replies; fetch insights. Cross-adaptation from X threads (F-30) is natural here.

**Discord (F-64).** Bot + webhooks. Primary uses: community hub (F-38) and **content-link sharing** (embeds with the model's link-in-bio / Fanvue link). Full server management + moderation + bot DMs. Not a public "feed"; `publish.*` maps to channel/webhook messages.

**Telegram (F-65).** Bot API posting to channels (media + **content links**), community management, bot DMs. Doubles as a Relay channel (see `L2.7`) and a private community hub (F-38).

**Facebook (F-66).** Graph API Page publishing (photos, Reels, links), insights, comment moderation. Shares the Meta auth/app with Instagram/Threads where applicable.

**Snapchat (F-67) — honesty required.** Snapchat offers no general organic-posting API for individual creators comparable to the others. The adapter therefore:
- Uses **Creative Kit / share flows** and **Public Profile** management **where available** for the account type.
- Otherwise degrades to **`manual-assist`**: the scheduler produces the asset + caption and dispatches a Relay task ("Post this to Snapchat now") with the media attached, so the human posts it in seconds from the phone.
- The UI/agents surface Snapchat as `manual-assist` so no one is misled into thinking it auto-posts (LBI-08).

## Cross-platform cascading & adaptation

- **Cascading (F-11):** templates like `X → +2h → IG → +1h → Threads`. The scheduler expands a template into `post_targets` with staggered slots; each fires under its platform's rate limiter and egress.
- **Adaptation (F-30):** the LLM gateway reformats one source post into platform-native forms (X thread → IG carousel copy → YouTube Short description → Reddit self-post), adjusting tone/length/hashtags per platform culture and ToS. Each adapted target still passes the ToS gate.

## Connector lifecycle & resilience

- **Versioned adapters** with contract tests against each API (or recorded fixtures). A platform API change trips a contract test, not production.
- **Capability feature-flags** per (model, platform, capability) so a revoked scope disables only that capability.
- **Rate limiters:** per-platform token buckets with documented limits, backoff, and jitter; a shared rate ledger prevents cross-job overrun.
- **Errors** flow to the Observability plane (`L2.9`); retriable failures go to the dead-letter queue with idempotent replay.
