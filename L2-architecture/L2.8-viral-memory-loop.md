# L2.8 — Viral Memory Loop (Self-Improving)

## Requirement satisfied

Remember posts that went viral, learn what made them work, and continuously get better at generating winners. A closed loop: **generate → post → measure → label → embed → retrieve → bias → repeat.**

## 1. Performance ingestion (F-79)

After a post publishes, an `ingest_metrics` job polls each platform connector's `read.insights` on a decaying schedule (dense early, sparse later) and writes to the `post_performance` hypertable: views, likes, saves, shares, comments, CTR to link, **conversions to Fanvue subs/PPV** (joined via Attribution + MCP), and for video, retention/avg-view-duration. Time windows (1h/6h/24h/7d) are rolled up by Timescale continuous aggregates.

## 2. Viral labeling (F-80)

Labeling is **dynamic and relative**, per platform and per model (a "viral" Reel for a 5k-follower model differs from a 500k one):
- Compute the post's percentile within the model×platform performance distribution over a trailing window.
- Cross a configurable percentile (e.g., ≥ p90 on the primary success metric for that platform — CTR-to-link and conversions weighted heavily since revenue is the goal) → label `high_performer`.
- Drift detection watches the distribution so thresholds track the model's growth (R-08).

## 3. Generative-recipe capture (F-81)

For each labeled post, snapshot the **full recipe** into `viral_recipes`:
`{ S3 shoot config (attire/environment/lighting/…), caption text + structure, hook (first line/thumbnail-text), hashtag set, posting time/day, format (Reel/Short/carousel/thread), platform, thumbnail feature descriptors, ToS score, realized metrics }`.
This is what makes success **replayable**, not just observable.

## 4. Embedding & index (F-82)

Embed the caption + hook (and optionally a vision embedding of the thumbnail) → store in `viral_embeddings` (pgvector, HNSW) keyed to `recipe_id`, filterable by model/platform. No external vector service; retrieval is a single SQL query.

## 5. Retrieval → generation bias (F-83)

At generation time, the Master Prompt Engine retrieves **top-K** recipes most similar to the intended theme for the target model+platform and injects them as **exemplars in S2** (TOKENKILLER-friendly; see `L2.5`). The generator is thereby biased toward patterns that demonstrably worked for *this* model on *this* platform — "here are 5 of your best-performing hooks/captions/formats; produce new work in that vein."

## 6. Explore/exploit (F-84)

A **contextual bandit** chooses among candidate arms — caption style, hook type, posting time bucket, format — per (model, platform, context). Reward = realized success metric (CTR/conversions, recency-decayed). The A/B winner-promotion signal (F-16) feeds the same reward. An **exploration floor** guarantees the system keeps trying novel variants so it doesn't overfit a stale pattern (R-08). Weights live in `bandit_state`.

## 7. Insight surfacing (F-85)

- A **"What's working"** dashboard panel: e.g., "Reels at 7–9pm with hook-style X convert 2.3× baseline (n=14)."
- The **calendar's optimal-time suggestions** (F-10) and **trigger-rule thresholds** (F-19) read from the same learned distributions.
- Periodic insight cards go to the Relay (F-85 ↔ F-28) so the operator learns what's working from their phone.

## 8. Scope & privacy (F-86)

- Learning is **per-model by default** (persona-specific).
- **Org-level cross-model pattern sharing** is opt-in and privacy-scoped (shares abstract patterns like "vertical video + question-hook at 8pm," never one model's private assets/data across tenants). RLS still applies to raw data.

## Loop integrity

- The loop only learns from **published** posts with **attributable** outcomes, so it optimizes for revenue-relevant virality, not vanity metrics.
- Recency decay keeps it current with platform algorithm shifts.
- All learning artifacts are tenant-isolated (LBI-01) and never leak into another org's generation.

```
        ┌────────────► generate (S0..S3, S2=top-K exemplars) ──► post ─┐
        │                                                              ▼
   viral_embeddings ◄── embed ◄── capture recipe ◄── label ◄── ingest metrics
        │                                                              │
        └───────────── bandit updates arm weights ◄────── reward ◄─────┘
```
