# L2.11 — CRM MCP Server & Agent Gateway

## CRM REST API (F-44)

OpenAPI/Swagger-documented endpoints with Bearer auth for external developers and webhooks. Every route enforces RBAC + RLS and is rate-limited per token. Full contract in `L3.0`.

## CRM as an MCP server (F-45)

The CRM hosts an MCP endpoint (`https://crm.<domain>/api/mcp`) so agents (OpenClaw, Hermes, Zeroclaw, or any MCP client) can invoke CRM tools natively. Δ vs v1: tokens are **capability-scoped, short-lived, per-agent, per-model**, and every tool call is audited (LBI-06) and rate-limited; a global kill switch (LBI-11) disables the surface instantly.

## Agent permission matrix (F-46)

Per-model tiers (also in `L1.0`):
- **Viewer** — read analytics, read queues/DMs.
- **Operator** — run pre-approved tasks (generators, DM replies, deploy links).
- **Manager** — create/modify content, schedule, modify links; **publishing requires human approval** (routes to Relay).
- **Autonomous** — full control including publishing and (via explicit dashboard-only grant) network config.

Publishing by any tier below Autonomous funnels through the Relay approval gate (LBI-04). Autonomous grants are dashboard-only and audited (R-07).

## Ingestible skill manifest (F-47)

The CRM serves a dynamic JSON manifest scoped to the agent's tier and model, so an LLM can ingest the CRM's functionality and operate it:

```json
{
  "crm_name": "AXIOM (Fanvue CRM Enterprise)",
  "agent_permissions": "Manager",
  "scope": "model_specific",
  "model_id": "uuid-1234",
  "token_ttl_seconds": 900,
  "available_tools": [
    {
      "tool_name": "crm_generate_photoshoot",
      "description": "Generate a 5-shot photoshoot sequence via the Master Prompt Engine.",
      "parameters": { "attire": "string", "environment": "string", "lighting": "string" },
      "requires_approval": true
    },
    {
      "tool_name": "crm_schedule_targets",
      "description": "Schedule approved post_targets to specified platforms/slots.",
      "parameters": { "bundle_id": "string", "platforms": "string[]", "slot": "iso8601" },
      "requires_approval": true
    }
  ],
  "operating_guidelines": "Adhere to Fanvue Creator Course. All public posts must pass the ToS Risk Engine. Publishing requires Relay approval at this tier."
}
```

Tools marked `requires_approval` cannot self-publish; they create bundles that surface on the Relay. The manifest advertises only tools the tier permits, so the agent physically cannot see privileged tools (capability confinement, echoing the Wasmtime-capability-host pattern).

## Token & rate model

- Tokens are minted per (agent, model, tier) with a 15-min TTL and a `kid` for rotation; refresh requires re-auth.
- Per-token rate limits + org budget caps; overuse trips backpressure, not silent drops.
- Revocation and the global kill switch invalidate tokens immediately.

## External developer surface

The same domain model is exposed via REST (Bearer) for webhooks/integrations, sharing the RBAC/RLS/rate-limit/audit machinery so there is one enforcement path regardless of whether a human, an agent, or a webhook is calling.
