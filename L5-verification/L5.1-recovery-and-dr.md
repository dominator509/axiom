# L5.1 — Recovery & Disaster Recovery

> How AXIOM survives failure without duplicate posts, lost work, or security regression. The single-box design keeps DR simple; durability comes from Postgres + R2, not from a sprawl of stateful services.

## 1. Failure modes & responses

<!-- prettier-ignore -->
| Failure | Detection | Automatic response | Operator action |
|---|---|---|---|
| Worker crash during publish or relay delivery | job lock stale | lease expires → the external-side-effect job is dead-lettered with an unknown-outcome incident; no automatic retry | reconcile the provider/channel outcome before any explicitly authorized recovery |
| Box reboot | health check | systemd/Coolify restarts services; PG queue intact (durable) | verify markers |
| Postgres down | connection errors | app fails **closed** (no publish); incidents raised | restore from backup |
| Platform API outage | connector errors | pre-dispatch failures back off; once provider I/O starts, the outcome is dead-lettered as unknown | retry only after provider reconciliation |
| Channel (Relay) unreachable | send failures | pre-dispatch failures back off; once delivery starts, the card job is dead-lettered as unknown | check bot and reconcile before retry |
| ToS engine failure | scan error | verdict defaults to `block` (never `pass`) | inspect model |
| Suspected compromise | anomaly / manual | flip kill-switch (LBI-12) → all egress stops | rotate keys, audit |

## 2. Backups

- **Postgres:** continuous WAL archiving + nightly base backup to R2 (separate bucket/region). PITR enabled.
- **R2 media:** versioned bucket; lifecycle keeps prior versions N days.
- **Secrets:** KEK in KMS (survives box loss); per-org DEKs re-wrappable.
- **Config/markers:** in git; `.axiom/markers` reconstructible from state if needed.

## 3. Restore drill (documented + tested)

1. Provision fresh box; install Coolify (`L4.1` steps 1–2, markers force clean re-run).
2. Restore Postgres via PITR to last consistent point.
3. Re-point R2; verify object integrity via stored `sha256`.
4. Re-wrap DEKs from KEK; app comes up **with egress disabled** (kill-switch default on restore).
5. Run `L5.0` matrix; only when green, flip egress on.

**RPO:** ≤ 5 min (WAL). **RTO:** ≤ 60 min (single-box rebuild). Both measured in a rehearsed drill, not assumed.

## 4. Data-loss guarantees

- Idempotency ledger + content-addressed assets ⇒ replays are safe.
- PG-backed queue ⇒ no in-flight job lost on restart (unlike an in-memory broker).
- Audit hash chain ⇒ any post-incident tampering is detectable.

## 5. Security-preserving recovery

Recovery never weakens invariants: RLS, fail-closed egress, and ToS-block defaults all hold during and after restore. Egress stays off until the full test matrix passes — recovery cannot accidentally resume publishing into an unverified state.
