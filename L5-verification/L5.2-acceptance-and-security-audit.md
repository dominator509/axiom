# L5.2 — Acceptance Criteria & Security Audit

> The final gate. AXIOM is accepted only when every criterion below is demonstrably met. This doubles as the security audit checklist.

## 1. Functional acceptance

- [ ] Runs on a **single box** (Hetzner + Coolify) with Cloudflare + R2; no per-service metered PaaS required.
- [ ] All **10 platforms** connect, validate, and publish (or assist honestly for Snapchat).
- [ ] **Link-in-bio Native** works with zero external providers; Fanlynks, Linktree, and Beacons remain blocked until their real adapters and unified analytics are implemented.
- [ ] **On-the-go control** from Telegram, iMessage, Signal, and Discord: approve / reject / edit / reschedule / publish-now.
- [ ] On generation, a **card** with preview + per-platform mock captions + hashtags + ToS verdict is pushed to the operator's channel.
- [ ] **Auto crash/bug reporting** captures injected faults; structured logs + traces + dashboards live.
- [ ] **Self-improving viral loop** turns performance into exemplars that measurably bias later generations; bandit explores + exploits.
- [ ] Every **v1 feature (F-01..F-88)** resolves in v2 — nothing removed.

## 2. Non-functional acceptance

- [ ] Prefix cache-hit **> 97%** on repeat generations (LBI-09).
- [ ] Cross-tenant read returns **0 rows** under RLS (LBI-02).
- [ ] Egress **fail-closed** proven; kill-switch halts publishing (LBI-03, LBI-12).
- [ ] Exactly-once publish under retry/double-tap (LBI-05).
- [ ] Monthly infra cost within the modeled band (`appendices/A1`), materially below v1.
- [ ] RPO ≤ 5 min, RTO ≤ 60 min in a rehearsed drill (`L5.1`).

## 3. Security audit checklist

- [ ] No plaintext credentials at rest or in logs (LBI-01); envelope encryption verified.
- [ ] Every org-scoped table has `org_isolation` RLS with `FORCE`; app role can't bypass (LBI-02).
- [ ] Egress default-deny; only whitelisted hosts reachable when enabled (LBI-03).
- [ ] Relay commands signed, single-use (nonce), expiring; replay + expiry rejected (LBI-06).
- [ ] Audit log hash chain verifies; tamper detectable (LBI-08).
- [ ] ToS engine fails to **block**, never **pass** (LBI-11).
- [ ] Adult-content Consent & Records Vault populated + access-controlled (`L0.1`).
- [ ] Secrets in KMS/secret store, not git; dependency + secret scans clean.
- [ ] Agent `requires_approval` tools cannot publish directly; RBAC + tier enforced (LBI-04).

### Grok OAuth media and text-only execution boundary (2026-09-11)

The operator selected Grok OAuth for image/video generation. Official Grok Build
source at `37949780c144e37df692e3d669051a21fec24f20` explicitly wires OAuth session
credentials into Imagine image/video tools, with per-user metering and tier gates
([credential configuration](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/crates/codegen/xai-grok-shell/src/agent/mvp_agent/agent_ops.rs)).
This supports pursuing the existing official CLI transport; it does not establish
an AXIOM media implementation, account entitlement or a third-party OAuth grant.

The same source inspection exposed an existing text-only transport assumption:
empty `--tools` means inherit, and denylist entries match exact tool IDs, not
permission labels such as `Bash` or `MCPTool`. AXIOM now selects a curated empty
`toolConfig`, disables default-tool injection and skill discovery, and explicitly
denies MCP dispatch IDs. Both chat and streaming launch-policy regressions failed
before the change and passed afterward; the full gateway suite passed 274 tests,
typecheck, build and lint (16 existing warnings). This is source/launch-contract
evidence, not a live adversarial CLI execution test. Installed Grok reported
`1.0.5 (5115b46bc9)`; its revision could not be resolved in the public source repo.

The subsequent real-CLI rehearsal **disproved the sufficiency of that patch**:
the installed binary still advertised 15 tools to the primary model, including
image and video tools. `scripts/rehearse-grok-tool-policy.mjs --isolated-fixture`
uses the actual compiled AXIOM transport and installed CLI with a fresh temporary
profile and a localhost synthetic model. It never generates real media or uses
a provider account. A nonempty recognized `search_tool` allowlist combined with
the existing deny of both `search_tool` and `use_tool` corrected the behavior.
Both chat and streaming now return the fixture text with zero tools advertised
on all four primary model requests. Auxiliary requests are checked separately
and may expose only the `session_title` structured-output schema. The harness
fails on unexpected tool exposure and cleans up its fresh profile and server.
Run `pnpm --filter @axiom/llm-gateway build` before this opt-in local rehearsal.

This is real installed-CLI compatibility evidence against a synthetic model,
not an OAuth entitlement test, hostile tool-call injection test, Linux production
execution test or media pipeline acceptance. No real OAuth credential values
were read, no generation credits spent, and no media capability was enabled.

Tracing generation into this transport also found the synchronous API's optional
caption-enrichment call omitted `userId`, although the subscription gateway
requires it. The route now forwards only the authenticated context identity;
request JSON cannot choose a subscription profile and the audit-only `system`
fallback is not forwarded. Two route regressions failed before and passed after
the change; all 519 API tests, typecheck, build and lint passed (160 existing
warnings). The build still warns about local auth-secret quality. This repairs
the caption-enrichment identity handoff, not image/video generation, worker
credential propagation or live provider authorization.

The unexposed media-transport draft is **not ready to wire into production**.
Official Grok source at the same pinned revision shows `image_to_video` reads
the model-supplied image path using `tokio::fs::read` before acquiring its video

The official hook guide also specifies fail-open handling for hook crashes,

sole tenant-file boundary. Post-response path validation protects artifact
ingestion, not an earlier source-file read/upload. Do not enable the draft's
video path until a mandatory pre-execution boundary has been demonstrated;
passing unit tests or an explicit-deny hook test is insufficient.

### CLI-only isolation exception and bounded evidence (M87)

The user authorized new architecture **only for CLI transport**. Grok media
now requires a Linux bubblewrap filesystem boundary with a fresh request home,
a separate per-user credential directory, cleared environment, private PID
namespace, and no repository/full-profile mounts. Missing or denied isolation
fails closed; Windows/macOS do not run media unisolated. This retains networking
for the official CLI and is **not** a network-egress control. Existing production
images have not been changed to enable nested namespaces or install this runtime.

`scripts/rehearse-grok-filesystem.mjs --isolated-fixture` passed using the real
command builder, Ubuntu bubblewrap 0.9.0 and a native Linux Node probe. The bare
process read a synthetic other-user file; isolation denied that read, a symlink,
parent-process access and inherited environment data. The authorized input and
atomic replacement in the synthetic credential directory remained usable. This
tests the OS boundary, not Grok's media implementation. The installed Grok 1.0.5
also passed `scripts/rehearse-grok-auth-path.mjs --isolated-fixture`: logout
changed only the selected synthetic credential store. Empty stores were a no-op
and did not constitute evidence. Live OAuth login/refresh is still unverified.
The official [credential-path and atomic-write contract](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/crates/codegen/xai-grok-login/src/storage.rs)
informs the layout. New login selection activates only after successful login;
failed reconnect preserves the legacy session and logout cannot resurrect it.
AXIOM does not read or migrate token values.

Independent candidate review found that the video tool can still select the
credential file or `/dev/zero` **inside** the sandbox before upstream image
validation. Therefore valid video requests now return 503 **before any CLI
launch**. A mandatory pre-read source-image argument restriction is still needed;
output validation and fail-open hooks cannot supply it. Image transport/result
collection is not exposed through the API, dashboard or worker. Live Imagine,
exact artifact layout, credential refresh, output retention/decoding, bounded
tool invocation and full asset/ToS/Relay lifecycle remain release gates. The
filesystem improvement does not establish production-ready media generation.

Local validation: 302 gateway tests, typecheck and build passed; lint had no
errors and 16 existing warnings. Existing real-CLI text policy rehearsal still
returned chat/stream text with zero primary tools. No real credentials were
read, no generation credits spent, and no database/container restarted.

### Queued Relay revision compatibility (2026-09-11)

New `relay.card` jobs carry the revision identity from the completed ToS scan.
Workers retire jobs that no longer match the bundle revision, and park matching
jobs while ToS is pending. Unversioned legacy jobs are treated as initial-revision
jobs: a legacy queued card for already-revised content needs a fresh ToS scan to
produce a revision-bound handoff. Existing provider reconciliation markers are
not removed or replayed by this change. Unit regressions cover this boundary;
concurrent revision versus external dispatch remains unverified.

### Relay row-lock rehearsal (2026-09-11)

The worker now reads the bundle with `FOR NO KEY UPDATE`, retaining its state
and revision until the executor transaction ends. This matches PostgreSQL's
[row-lock compatibility rules](https://www.postgresql.org/docs/16/explicit-locking.html#LOCKING-ROWS):
revision updates wait, while the independent dispatch marker can acquire its
foreign-key key-share lock. A stronger `FOR UPDATE` would block that marker.

`node scripts/rehearse-relay-locking.mjs --isolated-fixture` passed twice using
three real connections and fresh synthetic tables in the labeled disposable
PostgreSQL container. It reproduced an unlocked concurrent revision, rejected
the stronger lock's marker insert with the exact lock-timeout code, and proved
the selected lock lets the marker commit while a decision is already waiting.
The decision proceeded after release. Cleanup left zero rehearsal databases.
The executor lock-selection regression failed before the change and passes
afterward; all 122 worker tests pass. This manual rehearsal is not hosted CI,
the full application schema, live provider dispatch, or a complete concurrency
acceptance test. Slow provider calls can delay decisions until the transaction
ends; existing unknown-outcome reconciliation remains necessary.
