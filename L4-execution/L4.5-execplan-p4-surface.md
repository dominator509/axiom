# L4.5 — ExecPlan P4: Surface (Link-in-bio, Agents, Dashboard, Mobile)

**1. Objective & scope.** Deliver the outward-facing surface: optional/composable link-in-bio providers, CRM-as-MCP-server agents, the operator dashboard, and the mobile/PWA experience. This completes the product.

**2. Preconditions.** `L4.4` complete.

**3. Invariants touched.** All — this phase exercises the full stack end-to-end.

**4. Dependencies.** Hono BFF, front-end (dashboard + PWA), link-in-bio Native provider, future Fanlynks / Linktree / Beacons adapters, MCP server runtime, agent tiers (`L2.11`).

**5. Build steps.**
1. Native link-in-bio provider (default, self-hosted): pages, blocks, analytics → `post_metric.clicks`. → `linkbio.native.done`
2. Future adapters — Fanlynks, Linktree, Beacons — are not a completion claim for this release; implement and contract-test each before exposing a feature toggle (`L2.4`). → `linkbio.adapters.done`
3. CRM MCP server: expose tiered tools (Viewer→Autonomous), `requires_approval` tools return `bundle_id` to Relay, never publish directly (`L2.11`, `L3.0`). → `mcp.server.done`
4. Agent runtime + skill manifest; earned-autonomy graduation gates. → `agents.done`
5. Dashboard: connections, calendar, generation, approvals, analytics, audit, incidents. → `dashboard.done`
6. Mobile/PWA: installable, push, approve-from-notification (complements Relay). → `mobile.done`

**6. Config & secrets.** Provider API keys (only for enabled adapters) in secret store; agent tier grants in dashboard; no adapter required to run (Native suffices).

**7. Per-step validation.**
```bash
# link-in-bio optionality: run with ZERO external providers
axiom linkbio status | jq -e '.providers|length==0 and .native.enabled==true'
# external kinds must remain rejected until their adapters exist:
! axiom linkbio enable fanlynks linktree beacons
# agent approval-gate:
axiom mcp call crm_create_content | jq -e '.requires_approval==true and .bundle_id!=null'
```

**8. Integration validation.** Full user journey: connect accounts → generate → approve via Relay → publish to all 10 → Native link-in-bio shows first-party click analytics → an Operator-tier agent proposes content that routes to Relay for approval. External providers remain outside this release until implemented; removing all external link-in-bio providers leaves the system fully functional.

**9. Rollback.** Disable any adapter via toggle with no impact on Native; revoke agent tier to halt autonomous action; dashboard/PWA are stateless front-ends (redeploy to roll back).

**10. Idempotency.** Provider enable/disable idempotent; MCP tools inherit publish idempotency; agent actions gated + audited.

**11. Security checklist.** External adapters optional and sandboxed; agent `requires_approval` tools cannot publish directly; RBAC + tier enforced on every MCP tool; PWA push tokens scoped.

**12. Performance checks.** Dashboard TTI budget met; link-in-bio page p95 < 100ms (edge-cached); MCP tool round-trip within SLA.

**13. Artifacts.** Link-in-bio Native provider, MCP server + agents, dashboard, PWA, `.axiom/markers/L4.5/*`.

**14. Done-criteria.** Runs with zero external link-in-bio providers; agents operate within tier + approval gates; full journey green across all 10 platforms. External adapters require a separate completion milestone.

**15. Hand-off.** Product complete → `L5` verifies the whole against invariants and acceptance criteria.
