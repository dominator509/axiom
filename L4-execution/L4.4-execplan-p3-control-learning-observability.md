# L4.4 — ExecPlan P3: Control, Learning & Observability

**1. Objective & scope.** Wire the Relay control channel, the self-improving viral loop + bandit, and the observability/crash-reporting plane. After this phase the operator controls posts on the go, the system learns from performance, and failures self-report.

**2. Preconditions.** `L4.3` complete (bundles + ToS verdicts exist).

**3. Invariants touched.** LBI-04 (commands mutate state; workers publish), LBI-05 (exactly-once publish), LBI-06 (signed single-use commands), LBI-12 (kill-switch).

**4. Dependencies.** Telegram/Discord bots, iMessage + Signal bridges, GlitchTip (crash), Prometheus + Grafana + OTel, pgvector (from P0), Timescale (metrics).

**5. Build steps.**
1. Relay card renderer + channel senders (Telegram, Discord rich; iMessage, Signal text + keyword protocol) (`L3.3`). → `relay.send.done`
2. Signed-command ingest: token verify, nonce single-use, state transition, audit write (`L3.3 §3`). → `relay.cmd.done`
3. On generation → auto-push Relay card (job `relay.card`); publishing waits for approval (LBI-04). → `relay.flow.done`
4. Metrics poller → `post_metric` (Timescale); normalize to z-score. → `metrics.done`
5. Viral loop: label → embed → `viral_exemplar` (HNSW); retrieval feeds S2 (`L3.5`). → `viral.done`
6. Contextual bandit for style selection with exploration floor + fatigue guard. → `bandit.done`
7. Observability: structured logs, OTel traces, Prometheus/Grafana dashboards; GlitchTip auto crash capture; DLQ (`state='dead'`) + idempotent replay. → `obs.done`
8. Sev-1 auto-page to Relay (`incident.notify` → card). → `page.done`

**6. Config & secrets.** Bot tokens + bridge creds in secret store; `K_relay` derived per-org from DEK; alert routing config in git (non-secret).

**7. Per-step validation.**
```bash
# replay attack rejected (duplicate nonce):
axiom relay-cmd --replay | jq -e '.error=="nonce_used"'
# approval required before publish:
axiom gen --targets ig,tiktok && axiom assert bundle-state generated  # not publishing
# exactly-once: double-approve one target → one remote post:
axiom relay approve --twice | jq -e '.published==1'
# crash auto-reported:
axiom faultinject | curl -s localhost:glitchtip/api | grep -q captured
```

**8. Integration validation.** Full loop: generate → card lands in Telegram with per-platform captions + ToS verdict → operator `approve_all` → workers publish (idempotent) → metrics arrive → a high performer becomes a `viral` exemplar → next generation's S2 shows it. Kill-switch flip halts all publishing mid-flight.

**9. Rollback.** Kill-switch → immediate egress stop; disable Relay ingest (bundles stay `generated`, fail-safe); pause loop (retrieval falls back to playbook-only S2); observability is passive (no rollback needed).

**10. Idempotency.** Cards keyed by bundle; duplicate command nonces rejected; publish idempotency from `L3.4 §4`; DLQ replay is idempotent by design.

**11. Security checklist.** Every command signed + single-use + expiring; ToS-block disables approve; no channel can publish directly; audit chain covers all commands; crash reports scrubbed of secrets/PII.

**12. Performance checks.** Card delivery p95 < 3s; retrieval k-NN < 30ms; dashboard scrape healthy; bandit update O(1).

**13. Artifacts.** Relay subsystem, viral loop + bandit, observability stack, `.axiom/markers/L4.4/*`.

**14. Done-criteria.** On-the-go approve/reject/reschedule works from a phone channel; replay rejected; exactly-once proven; viral exemplar surfaces in a later generation; crash auto-captured; kill-switch halts egress.

**15. Hand-off.** Control + learning + safety-net live → `L4.5` adds the outward surface (link-in-bio, agents, dashboard, mobile).
