# L4.2 — ExecPlan P1: Connectors & Network Isolation

**1. Objective & scope.** Build the Rust egress plane with fail-closed network isolation, then the 10 social connectors + Fanvue MCP client, all publishing through it.

**2. Preconditions.** `L4.1` complete (all P0 markers). Rust toolchain present.

**3. Invariants touched.** LBI-01 (no plaintext creds), LBI-03 (fail-closed egress), LBI-07 (honest capabilities).

**4. Dependencies.** Linux netns tooling, nftables, Rust (tokio, reqwest, ring), connector SDKs per platform, Fanvue MCP endpoint.

**5. Build steps.**
1. Rust egress plane service: all outbound platform traffic runs inside a dedicated netns whose **default route is null**; explicit allow-rules per platform host are added only when egress is enabled. → `netns.done`
2. Kill-switch wiring: `kill_switch.egress_enabled=false` ⇒ allow-rules withdrawn (`L3.4 §5`). → `killswitch.done`
3. Credential vault path: connect flow envelope-encrypts tokens (`L3.1 §3`, `L2.12`); plane decrypts in-memory only. → `creds.done`
4. Implement `SocialConnector` for the 7 `api` platforms (IG, TikTok, YouTube, X, FB, Reddit, Threads). → `conn.api.done`
5. Implement `link_share` connectors (Discord, Telegram). → `conn.link.done`
6. Implement `assisted` connector (Snapchat) → Relay hand-off stub. → `conn.assist.done`
7. Fanvue MCP client (`L2.10`) for the Fanvue side. → `fanvue.done`
8. Capability resolution on connect → persist to `platform_connection.capabilities`. → `caps.done`

**6. Config & secrets.** Per-platform app credentials in Coolify secret store; per-connection user tokens envelope-encrypted at rest. Netns config declarative, version-controlled.

**7. Per-step validation.**
```bash
sudo ip netns exec axiom-egress ip route | grep -qv default   # no default route
# with egress disabled, outbound must fail:
sudo ip netns exec axiom-egress curl -m5 https://graph.facebook.com; test $? -ne 0
cargo test -p egress-plane
```

**8. Integration validation.** Connect a sandbox account per platform; `capability()` returns declared matrix (`L3.2 §2`); a dry-run publish with egress **off** is blocked at netns (fail-closed proof); with egress **on** for one allowed host, only that host is reachable.

**9. Rollback.** Disable egress (kill-switch) instantly; revert netns rules from version control; revoke test connections.

**10. Idempotency.** Connectors register by platform key; re-run SKIPs built connectors on marker match. Re-connecting an account rotates the encrypted token (no duplicate rows — unique constraint).

**11. Security checklist.** No plaintext token at rest or in logs; egress default-deny verified; only whitelisted hosts reachable when enabled; Snapchat honestly `assisted` (no faked publish).

**12. Performance checks.** Publish path added latency from netns hop < 5ms; connector p95 within platform SLA.

**13. Artifacts.** Egress plane binary, 10 connectors, Fanvue MCP client, capability records, `.axiom/markers/L4.2/*`.

**14. Done-criteria.** Fail-closed egress test green; all 10 capabilities resolve; sandbox publish (api) + link-share + assisted hand-off each demonstrated.

**15. Hand-off.** Publishing rails exist → `L4.3` adds generation + ToS intelligence feeding them.
