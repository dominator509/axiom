# L4.0 — ExecPlan Index & Roadmap

> Execution layer. Each ExecPlan is a self-contained, marker-gated build unit with the standard 15 sections (§ template below). Plans are ordered but each declares its own preconditions so a resumed session knows exactly where it is (LBI-10: marker-gated greenfield semantics — every step is SKIP-if-done or FAIL-if-conflict, never blind overwrite).

## ExecPlan 15-section template (every `L4.x` follows this)

1. Objective & scope
2. Preconditions (marker checks)
3. Load-bearing invariants touched
4. Dependencies (packages, services)
5. Build steps (ordered, each with a marker)
6. Config & secrets (how, not values)
7. Per-step validation commands
8. Integration validation
9. Rollback / recovery procedure
10. Idempotency & re-run behavior (SKIP vs FAIL)
11. Security checklist
12. Performance checks
13. Artifacts produced
14. Done-criteria (measurable)
15. Hand-off to next plan

## Marker convention (LBI-10)

Each build step writes a marker on success:

```
.axiom/markers/<execplan>/<step>.done   # contains: utc ts + git sha + checksum
```

- **SKIP:** marker present and checksum matches ⇒ step already done, skip.
- **FAIL:** marker present but checksum differs ⇒ conflict, stop and surface (never overwrite).
- **RUN:** no marker ⇒ execute, then write marker.

A resumed build re-enters at the first RUN step. Greenfield guards run *before* touching a workspace: a loud pre-flight aborts if it finds unexpected state.

## Global validation gates (must pass to advance a phase)

- `sh -n` clean on every shell script.
- `pnpm typecheck` / `cargo check` clean.
- RLS coverage test green (no org-scoped table without policy).
- Egress test: with kill-switch off, a publish attempt is *blocked at netns* (proves fail-closed).
- Prefix cache-hit metric ≥ target on a generation smoke run.
