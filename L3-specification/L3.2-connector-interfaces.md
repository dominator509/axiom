# L3.2 — Connector Interfaces & Capability Declarations

> Realizes the connector framework in `L2.3`. Every one of the 10 social platforms + Fanvue implements the **same** `SocialConnector` interface. Capabilities are *declared*, not assumed; the scheduler reads declarations and adapts (LBI-07: no silent capability faking). Where a platform has no publish API, the connector declares `publish: 'assisted'` and routes through the Relay instead of pretending success.

## 1. Core interface

```ts
export type Platform =
  | 'instagram' | 'tiktok' | 'x' | 'youtube' | 'reddit'
  | 'threads'   | 'discord' | 'telegram' | 'facebook' | 'snapchat';

export type PublishMode = 'api' | 'assisted' | 'link_share';
//  api         → full programmatic publish
//  assisted    → we prepare everything; human taps "post" (Relay hand-off)
//  link_share  → we publish by sharing a content link into the channel

export interface Capability {
  publish:        PublishMode;
  media:          Array<'image' | 'video' | 'carousel' | 'story' | 'short'>;
  maxMediaBytes:  number;
  caption:        { max: number; hashtags: boolean; mentions: boolean };
  scheduling:     'native' | 'internal';   // platform schedules vs we do
  metrics:        Array<'impressions'|'likes'|'comments'|'shares'|'saves'|'clicks'>;
  refreshMetrics: 'webhook' | 'poll' | 'none';
}

export interface PublishInput {
  connectionId: string;
  asset:        { r2Key: string; sha256: string; kind: 'image'|'video' };
  caption:      string;
  hashtags:     string[];
  idemKey:      string;                    // H(model,asset,platform,slot)
}

export interface PublishResult {
  mode:       PublishMode;
  remoteId?:  string;                      // when mode = 'api'
  handoff?:   RelayHandoff;                // when mode = 'assisted'
  sharedTo?:  string[];                    // when mode = 'link_share'
}

export interface SocialConnector {
  readonly platform: Platform;
  capability(connectionId: string): Promise<Capability>;
  validate(input: PublishInput, cap: Capability): Promise<ValidationReport>;
  publish(input: PublishInput): Promise<PublishResult>;   // MUST be idempotent
  fetchMetrics(remoteId: string): Promise<Partial<PostMetric>>;
  revoke(connectionId: string): Promise<void>;
}
```

**Idempotency contract:** `publish()` first checks `idempotency_ledger` for `idemKey`; a hit returns the stored result without re-hitting the platform (LBI-05). All network egress from a connector traverses the fail-closed netns (LBI-03, `L2.6`).

## 2. Per-platform capability declarations (authoritative)

| Platform | publish | media | scheduling | metrics refresh | notes |
|---|---|---|---|---|---|
| **Instagram** | `api` | image, video, carousel, story | native (Graph) | webhook+poll | Graph API; business/creator acct req. |
| **TikTok** | `api` | video, short | internal | poll | Content Posting API; direct post w/ audit. |
| **YouTube** | `api` | video, short | native | poll | Shorts = ≤60s vertical flag on upload. |
| **X (Twitter)** | `api` | image, video | internal | poll | v2 media upload + tweet. |
| **Facebook** | `api` | image, video, story | native (Graph) | webhook+poll | Pages API. |
| **Reddit** | `api` | image, video | internal | poll | per-subreddit rules engine. |
| **Threads** | `api` | image, video | native | poll | Threads Publishing API. |
| **Discord** | `link_share` | image, video | internal | none | webhook/bot posts content link. |
| **Telegram** | `link_share` | image, video | internal | none | bot posts content link + preview. |
| **Snapchat** | `assisted` | image, video, story | internal | none | no open publish API → Relay hand-off. |

> Snapchat is deliberately `assisted`: the system generates media, caption, and a ready-to-post package, then routes a Relay card so the operator posts in one tap. This is honest (LBI-07) and still fulfills "full support" as an end-to-end workflow — the human tap is the only step no public API permits.

## 3. Validation report

```ts
export interface ValidationReport {
  ok:        boolean;
  platform:  Platform;
  errors:    string[];   // hard blocks (e.g. video too long)
  warnings:  string[];   // soft (e.g. caption truncated)
  tosVerdict?: 'pass' | 'review' | 'block';   // from L2.10 engine
}
```

Validation runs **before** any publish and before a Relay card is sent, so the operator sees platform-accurate previews (correct caption truncation, aspect warnings, ToS verdict) rather than optimistic mocks.

## 4. Registration & resolution

```ts
const registry = new Map<Platform, SocialConnector>();
export function connectorFor(p: Platform): SocialConnector {
  const c = registry.get(p);
  if (!c) throw new Error(`no connector registered for ${p}`); // fail loud
  return c;
}
```

Capabilities are resolved per connection at connect-time and cached on `platform_connection.capabilities`; the scheduler never assumes a capability the declaration doesn't list.
