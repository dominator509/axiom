# L3.5 — Viral Memory Loop & TOKENKILLER Segments

> Formal spec for the self-improving loop (`L2.8`) and the prompt-cache segmentation (`L2.5`). The loop turns published performance into retrievable exemplars that bias future generation; TOKENKILLER keeps the growing exemplar context cache-cheap (LBI-09).

## 1. Loop stages

```
generate → post → measure → normalize → label → embed → store → retrieve → bias → (generate)
```

1. **measure** — `metrics.poll` fills `post_metric` (Timescale) for a target's decay window (default 72h, platform-tuned).
2. **normalize** — engagement → per-(model,platform) rolling **z-score** so a small account and a large one are comparable. `perf_score = z(weighted_engagement)`.
3. **label** — thresholds: `z ≥ 2 viral`, `1 ≤ z < 2 strong`, `-1 ≤ z < 1 baseline`, `z < -1 weak`.
4. **embed** — build a feature record + `vector(768)` from caption style, hook type, posting time bucket, hashtag cluster, media traits (from vision), platform. Store in `viral_exemplar` (HNSW index).
5. **retrieve** — at generation, k-NN (cosine) for the target (model, platform, intent) pulls top exemplars labeled `strong`/`viral`, recency- and diversity-weighted (MMR) to avoid mode collapse.
6. **bias** — retrieved exemplars populate the **S2** prompt segment (§4) as few-shot "what worked" guidance; a lightweight contextual bandit (§2) picks among candidate styles.

## 2. Contextual bandit (style selection)

- **Arms:** discrete style/hook/timing templates mined from `viral` exemplars.
- **Context:** model, platform, daypart, recent fatigue signal.
- **Policy:** Thompson sampling over Beta posteriors on a normalized reward = clipped `perf_score`.
- **Exploration floor:** ε_min keeps trying fresh arms so the system keeps discovering, not just exploiting past winners (guards against staleness).
- **Fatigue guard:** an arm's reward is penalized if the same hook was used recently for that model, preventing audience burnout.

Reward attribution flows back through `viral.label`; the loop is closed and continuous — it "keeps getting better" by construction while retaining exploration.

## 3. Anti-overfitting & safety

- Diversity (MMR) + exploration floor prevent collapse onto one viral gimmick.
- Exemplars older than a decay horizon lose retrieval weight (trend drift).
- ToS engine (`L2.10`) still gates every generation — the loop can bias toward engagement but never past the safety line (LBI-11).
- Cross-org isolation: retrieval is `WHERE org_id = current` under RLS; no org learns from another's data (LBI-02).

## 4. TOKENKILLER segment layout (LBI-09)

Stable prefix ordering, 64-token block alignment, append-only within a request:

| Seg | Content | Volatility | Cache |
|---|---|---|---|
| **S0** | persona / model system prompt | static per model | always hit |
| **S1** | playbook + ToS rules + platform rules | static per platform | always hit |
| **S2** | retrieved viral exemplars ("what worked") | semi-static (changes as loop learns) | mostly hit |
| **S3** | this task: prompt, target, constraints | dynamic | miss (intended) |

Rules: segments concatenate S0→S1→S2→S3; each padded to a 64-token boundary so a change in S2 never shifts S0/S1 alignment; S2 is versioned per (model,platform) and only re-emitted when the exemplar set materially changes, so most generations reuse the S0–S2 prefix and pay tokens only for S3. Target prefix cache-hit > 97% (measured; `L5`).

## 5. Interfaces

```ts
interface ExemplarQuery { modelId:string; platform:Platform; intent:string; k:number }
interface Exemplar { id:string; features:Record<string,unknown>; perfScore:number; label:string }
interface ViralStore {
  record(target:PublishedTarget, metrics:PostMetric): Promise<void>; // measure→store
  retrieve(q:ExemplarQuery): Promise<Exemplar[]>;                    // →S2
}
interface Bandit {
  choose(ctx:BanditContext, arms:Arm[]): Arm;
  update(arm:Arm, reward:number): void;
}
```
