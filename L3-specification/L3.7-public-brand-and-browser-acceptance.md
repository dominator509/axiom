Authority: owner-approved Lane 5 plan in this task, including the explicit
choices of application branding, deployment-wide name/tagline, safe defaults,
public read-only API, and browser sign-in/workspace acceptance. Canonical
spelling is **FanThynks**. This extends README's public-name versus technical-name
policy; it does not infer a tenant white-label or provider contract.

## B1: public projection

API startup reads only `AXIOM_BRAND_NAME` and `AXIOM_BRAND_TAGLINE`.
Values are trimmed, limited to 80 and 160 Unicode code points respectively,
and reject control characters or multiline text. Missing, blank, or invalid
fields fall back independently. Diagnostics identify field names only.

`GET /api/v1/brand` is public and read-only, with `Cache-Control: no-store`.
Its only data fields are `name: string` and `tagline: string | null`.
Default: `{"data":{"name":"FanThynks","tagline":null}}`.
A null tagline means the existing localized default; configured text is
authored once and displayed unchanged in all six UI languages.
No environment object, credentials, write API, or database storage is exposed.

## B2: rendered application identity

The API is the authority. Dashboard server rendering retrieves the public
projection with a two-second timeout and request-local reuse, never persistent
caching. Errors use safe defaults. Updating runtime settings requires an API
restart, not a dashboard rebuild.

Names reach metadata, wordmarks, navigation/accessibility labels and account
copy. Taglines reach existing tagline locations and metadata description.
Configured strings render as escaped text, never markup or interpolation
templates. Default wordmark styling, mark geometry, colors, icons, typography
and localized text are preserved.

Public product references use FanThynks. Engineering package/env/repository/DB
identifiers, historical receipts, external protocol identifiers and technical
examples retain compatibility. This lane does not add configurable mobile,
PDF, native link-page, or stored affiliate-program branding.

## E1: real isolated browser journey

Use real built dashboard/API images and Chromium, synthetic accounts, two
tenants and an unassigned account. Exercise HTTPS login, incorrect credentials,
anonymous denial, access-pending state, assigned workspace/tenant records,
reload/session restoration, owner-only and cross-tenant denial, sign-out and
subsequent denial. Check default and configured branding using identical images.

The harness creates its own labeled disposable database/network, random
credentials and ephemeral HTTPS proxy. It never loads .env, accepts a live
target, publishes database ports, uses production records, or copies CI secrets
into local runs. Browser certificate exceptions are fixture-only. Production
auth protections remain enabled. Cleanup runs on failure as well as success
and verifies removal by run labels. Do not retain credentials/session headers
in screenshots, traces, or logs.

## V1: required receipts

- Default/configured/missing/invalid fields, Unicode limits, escaped text,
  response projection, failure fallback and all six locale defaults.
- Sentinel secret absent from browser-delivered assets and HTML.
- Two complete passing browser runs with fresh fixtures and verified cleanup.
- Wrong-brand and stripped-cookie fault controls must produce the expected
  assertion failures, followed by an uninjected passing run.
- Existing HTTP smoke and dashboard/API/full test suites remain intact.
- Frozen lockfile, typecheck, lint, build, audit and independent browser CI job.
- Exact source SHA, command, passed/failed/skipped counts and CI/job URLs.

These checks prove the isolated Chromium journey only. They do not establish
production TLS, deployed operations, model inference, external provider
behavior or full production readiness. Merge remains owner-gated.
