# L3.4 — Queue, Idempotency & Kill-Switch

> Realizes the Postgres-backed queue from `L2.9` (replacing v1's Redis+BullMQ). One dependency fewer, transactional with domain writes, survives restart with no data loss. Publishing is exactly-once *observable* via idempotency keys (LBI-05). A global kill-switch halts all egress in one write (LBI-12).

## 1. Why Postgres queue (Δ vs v1)

v1 used Redis + BullMQ. AXIOM uses a `job` table (`L3.1 §8`) drained by workers via `SELECT … FOR UPDATE SKIP LOCKED`. Benefits: enqueue is in the *same transaction* as the domain change (no dual-write races), state is durable, DLQ is just `state='dead'`, and there's no separate Redis to host/secure/back-up. Throughput is far beyond this workload's needs.

## 3. Claim loop (worker)

```sql
BEGIN;
SELECT set_config('app.org_id', $org, true);
UPDATE job SET state='running', locked_by=$w, locked_at=now()
WHERE id = (
  SELECT id FROM job
   WHERE state='ready' AND run_after <= now()
   ORDER BY run_after
   FOR UPDATE SKIP LOCKED
   LIMIT 1
) RETURNING *;
COMMIT;
```

On success → `state='done'`. On error → `attempts++`, `run_after = now() + backoff(attempts)`, back to `ready`; when `attempts >= max_attempts` → `state='dead'` (DLQ) and an incident is raised.

Backoff: `min(cap, base * 2^attempts) ± jitter` (default base 5s, cap 1h).

## 4. Idempotency

**Publish key:** `idem_key = SHA256(model_id ‖ asset_sha256 ‖ platform ‖ slot)` where `slot` is the scheduled minute bucket (or `"now"`). Stored unique-per-org on `post_target` and mirrored in `idempotency_ledger`.

Publish path:
1. `SELECT result FROM idempotency_ledger WHERE org_id,idem_key` → hit ⇒ return stored `PublishResult`, **no platform call**.
2. Miss ⇒ call connector `publish()`.
3. On success ⇒ `INSERT INTO idempotency_ledger` + set `post_target.remote_id`, both in one txn.

Result: retries, double-taps on the Relay, and at-least-once queue delivery can **never** produce a duplicate post (LBI-05). `job.dedupe_key` additionally collapses duplicate enqueues of the same unit of work.

## 5. Global kill-switch (LBI-12)

```sql
CREATE TABLE kill_switch (
  org_id  uuid PRIMARY KEY,
  egress_enabled boolean NOT NULL DEFAULT true,
  reason  text,
  set_by  text,
  set_at  timestamptz NOT NULL DEFAULT now()
);
```

- Every `publish.*` and `*.card` worker checks `egress_enabled` **inside its txn** before any outbound call; `false` ⇒ job parks in `ready` with a delay and emits a single incident.
- Flipping to `false` is one row write, effective immediately, org-scoped.
- Complements the network-layer fail-closed default (`L2.6`): app-layer intent + netns enforcement are independent stops. Either alone halts egress.

## 6. Ordering & fairness

Per-model publish targets carry a soft ordering by `scheduled_for`; the picker's `ORDER BY run_after` gives rough FIFO. Per-platform rate buckets (`L2.3`) live in the worker and defer (re-queue with delay) rather than block a worker slot, so one throttled platform can't starve others.
