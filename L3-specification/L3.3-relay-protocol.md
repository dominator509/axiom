# L3.3 — Relay Control Protocol

> Wire spec for the on-the-go control channel (`L2.7`). On every generation, a **card** is pushed to the operator's chosen channel (Telegram / iMessage / Signal / Discord) carrying preview, per-platform mock captions, hashtags, and the ToS verdict. The operator drives the post lifecycle from that channel. Every state-changing command is **signed and replay-protected** (LBI-06). Commands never publish directly — they flip bundle/target state, and the normal worker path publishes (LBI-04).

## 1. Card schema (channel-agnostic canonical form)

```json
{
  "card_id": "uuid",
  "bundle_id": "uuid",
  "model": "aria",
  "asset": { "kind": "image", "preview_url": "https://.../signed.jpg", "sha256": "…" },
  "tos": { "verdict": "pass|review|block", "reasons": ["…"] },
  "targets": [
    {
      "platform": "instagram",
      "publish_mode": "api",
      "caption": "…platform-accurate, truncated to limit…",
      "hashtags": ["#…"],
      "warnings": ["caption truncated to 2200 chars"]
    }
  ],
  "actions": ["approve_all","reject_all","edit","reschedule","per_target","publish_now"],
  "expires_at": "2026-07-16T10:15:00Z"
}
```

Rich channels (Telegram, Discord) render this as buttons. Plain channels (iMessage, Signal) render a compact text card + a **keyword protocol** (§4). `preview_url` is a short-TTL signed R2 URL; media never lands in third-party cloud unencrypted beyond the preview grant.

## 2. Actions → state transitions

| Action | Effect | Guard |
|---|---|---|
| `approve_all` | bundle → `approved`; targets → `pending`→enqueue | ToS ≠ block |
| `reject_all` | bundle → `rejected`; no enqueue | — |
| `per_target approve/skip` | selected target(s) only | ToS ≠ block per target |
| `edit` | opens caption/hashtag edit (reply-with-text or web deeplink) | — |
| `reschedule` | sets `scheduled_for`; state `scheduled` | valid future ts |
| `publish_now` | bypasses schedule; enqueue immediately | tier ≥ Operator |

A `block` ToS verdict disables `approve`/`publish_now` for the affected target; the card shows the reason and offers `edit` (LBI-11: unsafe content cannot be one-tap shipped).

## 3. Signed command token

Every actionable button/keyword carries a token; inbound commands must present it.

```
token = base64url( nonce(16) || exp(8) || HMAC-SHA256(K_relay, card_id || action || nonce || exp) )
```

Verification (worker side):
1. Parse `nonce`, `exp`, `mac`. Reject if `now > exp`.
2. Recompute HMAC with per-org `K_relay`; constant-time compare.
3. `INSERT INTO relay_command(nonce…)` — the `UNIQUE(org_id,nonce)` makes replay a duplicate-key failure (single-use, LBI-06).
4. Only then apply the state transition and write `audit_log`.

`K_relay` is an org-scoped key derived from the org DEK (`L2.12`), rotated on demand. iMessage/Signal (no button metadata) embed a short `code` mapping to the token server-side, so the operator never pastes crypto.

## 4. Text-channel keyword protocol (iMessage / Signal / any plain channel)

```
<code> ok            → approve_all
<code> no            → reject_all
<code> ig ok         → approve instagram target only
<code> ig no         → skip instagram target
<code> at 18:30      → reschedule all to today 18:30 (org tz)
<code> cap <text>    → replace caption (prompts platform if ambiguous)
<code> go            → publish_now
<code> ?             → re-send the card
```

`<code>` is the short human-friendly handle (e.g. `A3F`) bound to the signed token. Unknown or expired codes get a safe re-send, never a silent drop.

## 5. Delivery & fallback

- Card send is a job (`kind='relay.card'`); on channel failure it retries with backoff and, after N failures, falls back to the next configured channel and raises a low-sev incident (`L2.9`).
- Inbound commands arrive via each channel's webhook/bot; the ingest verifies the token (§3) before doing anything.
- If **no** channel is reachable, bundles remain in `generated` (never auto-publish) — fail-safe (LBI-04).

## 6. Security summary

Signed + single-use + expiring tokens (LBI-06); ToS-block gating (LBI-11); commands mutate state only, workers publish (LBI-04); every command audited with hash chain (LBI-08); preview URLs short-TTL and scoped. This closes the "control from anywhere" requirement without turning a chat channel into an unauthenticated publish button.
