# L1.2 — Non-Functional Requirements & User Journeys

## Non-functional requirements

| ID | Category | Requirement |
|---|---|---|
| NFR-01 | Cost | Whole system runnable on one ≤€100/mo box + Cloudflare + R2 for 1–20 models. No mandatory per-MAU or per-invocation vendor. |
| NFR-02 | Performance | Dashboard TTI < 2.5s on mobile 4G; media watermark/transcode of a 60s 1080p clip < 15s on the Rust plane; publish job dispatch latency < 2s from approval. |
| NFR-03 | LLM efficiency | ≥97% prompt-token cache-hit across providers that support caching; local vLLM fallback keeps generation available at zero marginal API cost. |
| NFR-04 | Availability | Core publishing path 99.5%/mo; graceful degradation if any single connector or the LLM gateway is down (queue + retry, never drop). |
| NFR-05 | Security | All LBIs continuously verified; secrets never at rest in plaintext; audit chain verifiable. |
| NFR-06 | Isolation | Zero cross-model egress association under normal operation and under tunnel failure (fail-closed). |
| NFR-07 | Recoverability | RPO ≤ 15 min (WAL-shipping/PITR), RTO ≤ 1h; every job type has a documented, idempotent replay. |
| NFR-08 | Observability | Every request/job has a correlation ID; every crash produces a captured, deduped report within seconds. |
| NFR-09 | Scalability | Multi-tenant from day one; horizontal add of worker instances without schema change; queue is Postgres-backed and shardable. |
| NFR-10 | Portability | No hard vendor lock-in; every managed dependency has a self-hosted swap-in documented in `L2.1`. |
| NFR-11 | Mobile-first | All operator-critical actions (approve/edit/reschedule/kill switch) reachable from phone via dashboard or Relay. |
| NFR-12 | Honesty | UI/agent never offers a platform action the connector's capability matrix marks unsupported. |

## Key user journeys

### J1 — Generate → control from phone → publish
1. Cron (or operator) triggers the Photoshoot Auto-Generator for Model A.
2. Master Prompt Engine (S0 persona + S1 playbook + S2 viral exemplars + S3 config) generates 5 image prompts + captions; images produced; each variant scored by the local ToS vision model per target platform.
3. **Relay** pushes a card to the operator's Telegram: preview, 3 caption variants, per-platform hashtag sets, ToS scores (e.g., IG 78/thr 20 ⚠, X 78/thr 85 ✓), targets.
4. Operator taps **Approve for X + Reddit only**, edits the caption inline via reply, sets a price, reschedules to 8pm.
5. Signed command hits the CRM; state → Scheduled; audit entry appended.
6. At 8pm, worker binds Model A's egress (fail-closed), runs Pre-Post Script, publishes via the X and Reddit connectors with idempotency keys, and to Fanvue via MCP.
7. Performance ingestion begins; if it crosses the viral threshold, the recipe is embedded into the viral store for future exemplar injection.

### J2 — Link-in-bio with no external provider
1. Operator creates Model B; no link-in-bio provider is enabled → the **Native** provider serves `b.linkdomain.tld` from the edge automatically. Nothing external is deployed.
2. Linktree, Beacons, and Fanlynks remain future adapters in this release; the dashboard rejects them until their external provisioning/OAuth and analytics paths exist.

### J3 — Crash → auto-report → auto-page
1. The TikTok connector throws on a malformed API response.
2. GlitchTip captures the stack trace, groups it, tags the release and correlation ID.
3. Severity classifier marks it Sev-2 (single connector, retriable); job goes to the dead-letter queue.
4. If it crosses the crash-loop threshold, the incident auto-pages the operator via the Relay with a one-tap link to the incident and a **Pause TikTok connector** button.

### J4 — Viral loop improves generation
1. Over two weeks, Model A's Reels posted 7–9pm with a specific hook style convert 2.3× baseline.
2. Those posts are labeled high-performers; their recipes embedded.
3. Next generation for Model A retrieves those exemplars into S2; the bandit shifts weight toward that hook/time; the "What's working" panel surfaces the insight; the calendar's optimal-time suggestion updates.

### J5 — Global kill switch
1. Operator taps kill switch (dashboard or Relay).
2. Within 5s all queues drain-pause, all publishing and DM/relay agents suspend across every model; action audited.
3. Re-enable is a separate explicit action.
