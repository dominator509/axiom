# L0.0 — Governance Charter & Load-Bearing Invariants

## Charter

AXIOM is a multi-tenant CRM for operating multiple Fanvue talent profiles and their social ecosystems. It is built **solo-operator-first** but **multi-tenant from day one** (RLS-enforced), so scaling to an agency requires no re-architecture. Governance exists to keep the system cheap to run, safe to operate, and honest about platform constraints while the feature surface grows.

Design tenets, in priority order:
1. **Fail closed.** Any ambiguity in egress, publishing, or authorization resolves to "do nothing" rather than "leak / double-post / over-permit."
2. **Self-host by default.** Every managed dependency must have a self-hosted swap-in. No single vendor is load-bearing.
3. **Honest capabilities.** The system never claims to automate a platform action its official API forbids; it degrades to link-share or manual-assist and says so.
4. **Human-in-the-loop for publishing.** Autonomous agents may draft, schedule, and analyze; publishing to a live audience passes an approval gate unless explicitly granted Autonomous tier per model.
5. **Everything is observable and reversible.** No action without a correlation ID, an audit entry, and (where it mutates the world) an idempotency key and a documented rollback.

## Load-Bearing Invariants (LBI)

These are the invariants the entire system is verified against (see `L5-verification/`). Violating any one is a release blocker. They are numbered so ExecPlans and tests can cite them.

**LBI-01 — Tenant isolation.** Every row-returning query runs under Postgres RLS with `app.current_org` set from the authenticated principal. No code path may read or write across org boundaries. App-layer tenant guards duplicate the check (defense in depth).

**LBI-02 — Fail-closed egress.** A job that must use a model's dedicated egress executes **only** inside that model's bound network context (proxy/WireGuard/netns). If the tunnel health check fails, the job aborts and is re-queued; it must **never** fall back to the host's default route. Cross-model IP association is treated as a Sev-1 incident.

**LBI-03 — Publish idempotency.** Every outbound publish carries a deterministic idempotency key `(model_id, asset_hash, platform, scheduled_slot)`. A retry with the same key must be a no-op that returns the prior result. No action may double-post.

**LBI-04 — Approval-gate integrity.** A transition from `Draft`/`AwaitingApproval` to `Scheduled`/`Publishing` may occur only via (a) an authenticated dashboard action, or (b) a **signed, unexpired, single-use** Relay command. Forged or replayed commands are rejected and logged.

**LBI-05 — Secret confidentiality.** Social tokens and proxy credentials are stored only as envelope-encrypted ciphertext. Plaintext exists solely in worker memory during execution and is zeroized after. No secret is ever logged, echoed to the Relay, or returned by any API/MCP tool.

**LBI-06 — Audit immutability.** Every state-changing action appends a hash-chained entry `hash_n = H(hash_{n-1} ‖ entry_n)`. The chain is verifiable end to end; a break is a Sev-1 tamper alarm.

**LBI-07 — ToS gate.** No asset is published to a platform whose ToS risk threshold is exceeded without an explicit, audited human override. Overrides are per-post, per-platform, and never blanket.

**LBI-08 — Capability honesty.** A connector may only invoke actions its declared capability matrix marks `native`. `link-share` and `manual-assist` actions route to the Relay/queue for the appropriate handling; they never silently no-op.

**LBI-09 — TOKENKILLER ordering.** Every LLM call assembles the prompt as ordered segments `S0` (system/persona, static) → `S1` (playbook/ToS rules, static) → `S2` (retrieved viral exemplars, semi-static) → `S3` (task variables, dynamic). Static segments are byte-stable and block-aligned to preserve provider prefix caches. Reordering that breaks cache is a defect.

**LBI-10 — Greenfield marker discipline.** Idempotent setup/deploy steps distinguish SKIP (already satisfied) from FAIL (conflicting state). Ledgers are append-only. A pre-workspace guard aborts loudly if it detects an inconsistent partial state rather than silently overwriting.

**LBI-11 — Global kill switch.** A single operator action drains all queues and suspends all publishing and all DM/relay agents across every model within 5 seconds, and is itself audited. Re-enabling is a separate, explicit action.

**LBI-12 — Consent record precondition.** No model profile may publish until a valid, in-date consent/records set exists in the Consent & Records Vault. Expiry blocks new publishing and pages the operator.

## Amendment protocol

Invariants change only via a documented ADR (Architecture Decision Record) appended to `L0-governance/adr/` with rationale, the LBIs affected, and the migration/verification impact. ExecPlans reference the ADR that authorized any deviation.
